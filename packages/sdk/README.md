# @decks/sdk

Every Decks call, three ways, all made from one table (`packages/api`) and all calling one
endpoint, `POST /api/v1/<name>`:

| Form | For | Looks like |
| --- | --- | --- |
| TypeScript, `src/index.js` | apps, the browser, node scripts | `await decks.canvas.move(path, { beside: "n1" })` |
| The `decks` command, `bin/decks` | an agent's shell, any script | `decks canvas move canvases/plan/cards/q3/index.html --beside n1` |
| MCP, `mcp/server.mjs` | agents that can only call tools | the tool `decks_canvas_move` |

Calls are named noun then verb, in seven groups: `canvas` (everything on one canvas, cards
included), `card` (the deck's cards, canvases, frames), `agent` (you and the others),
`view` (what the person's screen shows; never writes a file), `apps`, `web` (the shared Chrome
tab), and `ports` and `now`. Every canvas call takes `{ canvas }` last; left out, it is
`decks.here()`, which is your home canvas. No call changes which canvas you are on except
`agent.update({ canvas })`.

One file, no dependencies, Node 18+ or a browser. The server runs no code of yours: each call is
one call with its arguments as JSON, checked against the table before anything runs.

```js
import { decks } from "@decks/sdk";          // DECKS_URL and DECKS_TOKEN from the environment

const { path } = await decks.card.create({ title: "Q3 revenue is up a fifth" });
await decks.canvas.insert({ type: "card", card: path }, { beside: "n1" });
await decks.canvas.fit(path);
await decks.view.focus(path);
```

```sh
p=$(decks card create --title "Q3 revenue is up a fifth" | jq -r .path)
decks canvas insert --type card --card "$p" --at.x1 0 --at.y1 0
decks canvas fit "$p"
echo '[{"op":"delete","id":"n1"}]' | decks canvas batch -
decks agent send Rune --task "Look at $p now"
decks help canvas insert
```

## Who is calling

Every call carries a token (`Authorization: Bearer`), and who is calling is that token alone: no
header, address or machine says it.

| Caller | Its token |
| --- | --- |
| An **agent** | Decks puts `DECKS_URL`, `DECKS_TOKEN` (the agent's own) and the `decks` command in each agent's shell |
| A Decks **server app** | Decks sets `DECKS_URL`, `DECKS_TOKEN` (the app's own, taken back when it stops) and `DECKS_SDK` (this file's path): `const { decks } = await import(process.env.DECKS_SDK)` |
| The **person** at a terminal | `decks login` with a code from `decks pair code` keeps a token in `~/.decks/token`, one per harness address; `decks logout` takes it back |
| Anything else | `connect({ url, token })` |

An app's first call makes Decks ask the person whether that app may use the stage, and each call
is noted in the conversation on screen.

## What to know

- A call answers with its value. The notes it adds (what `decks.canvas.fit` measured, where an item went) go to
  stderr in Node, or to `connect({ notes })`; `decks.call(verb, args)` gives value, notes and
  pictures together.
- A refused or failed call is a `DecksError` with `message`, `status` and `notes`.
- The `decks` command prints a string value as it is (so `$(decks card url …)` is the address) and
  anything else as JSON; notes and refusals go to stderr, and a refusal exits with 1.
- `src/index.d.ts`, the verb list in `src/index.js` and `src/verbs.json` are generated by
  `node --import tsx scripts/gen-sdk.mjs` from the table; a test fails when they drift.
- `DECKS_TOOLS=canvas,card,view` narrows the MCP server to some groups.
- `decks.events(onEvent, { types })` and `decks events [type…]` follow every change as Decks
  broadcasts it (`GET /api/v1/events`, Server-Sent Events), the same frames a browser hears.
  `{ reconnect: true, refused }` opens it again after it ends, until the harness refuses the token.

## From a page on another site

A front end such as Decks Studio needs nothing but this file to talk to a harness:

```js
import { connect } from "@decks/sdk";
const harness = connect({ url: "http://127.0.0.1:4329" });
const { token } = await harness.connectStudio({ studio: location.origin, key }); // or pairSite({ code })
const decks = connect({ url: "http://127.0.0.1:4329", token });
await decks.hello();                                     // its name, and whether the token works
const { pass } = await decks.canvasPass("plan");         // a canvas frame's pass, an hour
open(await decks.appUrl("notes"));                        // an app in a tab, with an app pass
const path = await decks.upload(file);                    // into assets/
const settings = await decks.request("/api/harness");     // any other door, with the token
```

The token goes in the `Authorization` header of every request and never in an address; a frame or a
tab carries a pass instead. `keepCanvasPass(canvas, onPass)` keeps a canvas's pass fresh while it
is shown, and `stop()` ends it.
