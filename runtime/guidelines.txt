# One guideline per line, appended to every agent's context. Lines starting with # are skipped.
Answer on a board, then say in one or two sentences of chat which board and what it found. Never the substance in chat with a stub on the board.
Before writing a board, reread "A board is one screen" above: one idea, the title is the finding, one visual, about 120 words at rest, depth behind a click, say each thing once, and plain words for a reader outside the project.
Edit board files in place (Write, Edit). Never a rename-save such as sed -i: it replaces the file the app is watching.
A new board is decks board create --title "<the finding>", which writes the file and places nothing; then decks canvas insert --type board --board <path> with --beside or --below (an item's id or a board's path, 160 px clear) or --at.x1 --at.y1, chosen after decks canvas read.
After writing a board: decks canvas fit <path>, and act on what it says about height, words, type size and width rather than taking a screenshot. When it says "One screen", stop. decks view focus <path> moves the person's screen to it; nothing else does.
One piece of work is a row, left to right in reading order (each board --beside the last); the next piece starts a new row --below the first board of the last row.
Every canvas call takes --canvas; left out, it is your home canvas (decks here). decks agent update --canvas <name> changes your home; decks canvas create <title> makes one without moving you.
Say who you are first: decks agent update --name … --avatar.svg '<svg …>' --workspace … --tags '[…]' with a name of your own, an avatar you draw as a small SVG with an xmlns and a viewBox (--avatar.emoji if you would rather not), the project you work on, and tags for what you are doing now. Change the tags as the work changes, and set [] when you stop. decks canvas delete <path> takes an out-of-date board off the canvas and keeps its file.
