How the changed mark is wired

Summary

The server already knows who named a board, and it is the one that has to start saying when. The browser decides the other half, because only the browser knows what is on screen. The rule itself is on the rule board, and the drawing is on the look.

Where each half is decided

Where the change goes

WhereWhat changes
packages/protocol/src/deck.ts namedAt?: number beside modifiedAt and seenAt
apps/server/src/boards/authors.ts The note keeps { who, at }, with a say() that is idempotent for one act. A bare string in a file written before this still parses, as a writer with no time
apps/server/src/boards/service.ts wrote() stamps the time and broadcasts it. The canvas editor's patch now goes through wrote(path, "you") rather than setting the byline itself, so the person's own act is timed like an agent's
apps/server/src/deck/loader.ts The act time rides across a re-read, the way the byline already did: the loader re-describes the file and knows no authors, so a re-read used to drop both
apps/web/src/chrome/dispatch-view.ts isNews reads the act and falls back to the file, agoLabel names the age for a chip, and a shelf sorts by the newest act rather than the newest file
apps/web/src/app/watching.ts new The you were watching half, as its own module rather than inline in the frame handler, so the rule can be tested without a model. frames.ts calls it on board.changed and sends board.seen
Gallery.tsx, DispatchView.tsx, AgentPill.tsx, App.tsx, dispatch.css The four carriers, the accent count on a shelf, and the dot on the Boards tab
Tests Seven cases in dispatch-view.test.ts, four in watching.test.ts, two in authors.test.ts, wrote.test.ts rewritten for the act time, and a new e2e/checks/news.mjs whose 16 assertions read the mark out of the DOM
