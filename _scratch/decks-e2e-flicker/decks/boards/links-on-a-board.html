Links on a board

Summary

A link on a board no longer navigates the board. A link to another board in the deck opens that board on the canvas, beside the one that carried it; every other link opens in a tab of its own, so the board being read is still the board in the frame. Until now both replaced the board with whatever the link pointed at, at an address the reader could not get back from.

Result

What the link points atWhat a click does
a board in this deck — href="risks.html" that board goes on the canvas, 32px to the right of the board that linked to it, and both are framed
somewhere else — href="https://…" a tab of its own; the board does not move
a file in the deck that is not a board — href="../assets/sketch.svg" a tab of its own; the board does not move
a board file this deck does not hold — href="not-written-yet.html" a notice saying there is no board there; nothing opens
a jump inside the board — href="#top" the board scrolls, as it always did

Method

Five files, and a link only crosses two of them.

runtime/lib/board.jsthe click: decides what the link is, and for anything that is not a board puts target="_blank" on the anchor so the browser opens the tab itself
apps/web/src/canvas/board-links.tsthe app's half of the one message a board link sends: same-origin, from this frame, and one path inside the deck
apps/web/src/App.tsxopenLinkedBoard: plays the board, places it beside the link's own board, frames both, or says there is no board there
apps/web/src/canvas/BoardFrame.tsx, Present.tsxthe two frames a board is drawn in, so a link works when the board is presented too
runtime/AGENTS.md.tmpl, runtime/skills/board-authoring/SKILL.mdthe guidance: cite by link, and when a board needs more room, write the next board and link to it

The decision is made in the board, not in the app, and that was measured. A tab can only be opened from the click itself: a window.open in the app's message handler — the obvious design, where the app is the only thing that knows the deck — opened an empty window and never navigated it. So the frame classifies by the board-file glob (.html, .md) and opens its own tabs, and only a board link travels. The cost is one extension list with two readers, the same bargain familyOf already makes with embedFamily.

Checked twice. In a real browser, e2e/checks/board-links.mjs — 13 assertions, green — drives the fixture board at 88% zoom and checks all five rows above, the presented board's own frame, and that the frame's address never changes. The zoom is not padding: a board below half zoom takes no pointer events at all, which is what made the first version of this check assert about clicks that never landed. And in the unit suite, board-links.test.ts pins the two guards: a message from another window, and a path out of the deck.

326 web tests and 947 across the repo, all green; tsc --noEmit clean on every package. The whole browser suite — 22 checks, 496 assertions — is green on the merged tree, including the 12 assertions of the code-highlighting check that landed first, and the four other checks that read the fixture board this touched.
