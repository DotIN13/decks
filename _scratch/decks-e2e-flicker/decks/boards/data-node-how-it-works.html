No — and the handle is not an id in the file

A handle goes on every node that has bytes of its own and is not inside a leaf: every container, and every leaf. It is how a press finds a node, and nothing else — the file never contains one, and never learns it exists. The address of an edit is still data-id plus the path counted in the tree.

Node Handle Why In the deck
A container — <section class="card">, a document's body, a list Yes It can be moved, deleted, reordered, resized — every verb a container has. 15,009
A leaf — a <h3>, a <p>, a table cell Yes It is one run of words: a caret goes in it, and its whole content is what an edit replaces. 41,648
A mark inside a leaf — <b>, <a>, <code> No By policy: a run of words is one leaf, marks and all. Half a sentence is not a thing to select, and the caret walks through a link rather than stopping at it. Giving these handles would invite a verb the model does not have. 32,318
A text node No Nothing to carry an attribute, and nothing to address: a run of text is its element's content, which is the leaf above. —
An element the parser implied — a <tbody> no byte corresponds to No No bytes, so no range to splice. A step in a path, never a target. 338
What a script drew inside a panel No It is not in the tree at all — and so, mechanically, not selectable. The panel itself is, and it is edited as its source. —

Counted over this deck: 540 boards, 89,313 elements — 56,657 handles, 338 without bytes, 32,318 marks inside runs.

Five steps, and two properties

Step
1 — assign During the walk, in document order: data-node="n412". A counter, so the same board gives the same handles twice running.
2 — serialise The tree goes back out as a document with the handles in the markup, and is written into the iframe.
3 — the browser parses it They are ordinary attributes, so they survive — and this is the parse that runs the board's scripts and applies its stylesheets.
4 — collect [data-node] → element → node. That map is the only thing that pairs a DOM element with a tree node; the node's own address is data-id plus a path.
5 — a press event.target.closest("[data-node]") → the node → the path, counted in the tree → the server splices the range it found in its own parse.

Never written back: the handle exists in the editor's frame and nowhere else. No layout effect: it is an attribute, and no board's stylesheet knows the name — mine is data-node for that reason.
