Goal

A second tab that wakes up must not spend a token the first tab already spent. One session, two tabs, no re-login.

Approach

Treat a refresh as a claim: first claim wins, the losers wait for its answer.

  • Server: short-lived lock per token family
  • Client: one shared promise per tab group
The race is small
~240ms, but a laptop waking from sleep hits it nearly every time.
Open question. Rotate on every refresh, or only when the family is suspected? Rotating always means more windows, not fewer — see the risks board.

## The sequence 1. Tab A and tab B both see a 401. 2. Both ask to refresh with the same token `t0`. 3. The lock admits one. It gets `t1`, and writes it where both can see. 4. The other wakes, finds `t1`, and retries with it. Cost per refresh stays $O(1)$: one write with a TTL, one round trip for the losers.
